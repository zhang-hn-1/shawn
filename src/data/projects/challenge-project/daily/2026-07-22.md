## 验证结果
- SNL 数据处理管线已经真实运行，并完成 95 个 LFP 文件的处理。
- SNL 数据包含电流、电压、温度、容量、能量、内阻和 EIS 等信息。
- 当前 SNL 数据中的 SOC 和 SOH 字段仍为空，暂时不能直接用于完整监督训练。
- SNL 数据没有完整寿命衰减轨迹，不能直接承担 SOH 主模型训练。
- Stanford 49Ah 数据尚未完成真实字段验证。
- 当前仓库中的结果登记主要为数据预处理结果，没有正式模型指标。
- 已形成从原始数据处理到 SOC/SOH 联合输出的核心流程。

## 问题与阻塞
- Stanford 49Ah 原始数据尚未正式接入。
- 当前缺少完整寿命衰减数据和可靠 SOH 标签。
- SOC 标签生成规则尚未最终确定。
- 工况识别和动态事件分割规则尚未形成具体阈值。
- 最终模型尚未进行基线训练和结构验证。

## 今日决策
- 将现有仓库定位为基础数据工程仓库，不将其视为两个已经完成的模型版本。
- 保留现有 SNL 数据读取和质量检查代码。
- 数据处理模块作为项目的重要创新部分，重点研究动态工况分割、事件提取和物理特征增强。
- 将混合动力工况中的电流突变和充放电切换作为电池状态辨识信息，而不是全部作为噪声删除。
- SOC 使用短时间尺度序列，SOH 使用事件级和循环级长时间尺度序列。
- 最终模型暂定采用多尺度因果卷积与 Mamba 结合的双时间尺度结构。
- SOH 分支输出的有效容量和内阻信息用于辅助 SOC 估计。
- 模型中加入安时积分、电压重构和 SOH 慢变化等物理约束。
- 最终模型除输出 SOC 和 SOH 外，还应输出容量、内阻和估计置信度。

## 明日提示词

请继续推进复杂动态工况下混合动力车辆磷酸铁锂电池 SOC/SOH 高精度估计项目。

当前已经确定两个核心方向：

1. 面向混合动力动态工况的多尺度数据处理模块。
2. 物理约束双时间尺度 SOC/SOH 联合 Mamba 模型。

请按照以下顺序开展明日工作：

第一步，检查 `zhang-hn-1/zhn-jiebang` 仓库中的现有文件，将文件划分为数据读取、数据清洗、质量检查、结果输出、图表生成和模型开发六类，并说明每个文件是否可以继续使用。

第二步，建立数据集责任表，明确每个数据集是否包含真实 SOC 标签、真实 SOH 标签、完整寿命轨迹、不同温度、不同倍率、动态工况、异常工况和 EIS 数据，并确定其用于训练、验证还是测试。

第三步，设计 SOC 标签生成规则，明确初始 SOC、积分起点、电流方向、有效容量、库仑效率、标签来源和标签可信度。

第四步，设计 SOH 标签规则，明确容量型 SOH、内阻型 SOH 和 EIS 特征的使用方式，不得将程序循环编号或倍率变化直接作为老化标签。

第五步，设计数据处理流程，包括时间同步、重采样、异常检测、缺失标记、因果去噪、电流零偏校正、工况识别、动态事件分割和物理特征提取。

第六步，确定短时 SOC 窗口和长时 SOH 窗口，并给出模型所需的输入张量、标签张量、质量掩码、工况标签和电池编号。

验收标准：

- 每个数据集的用途明确。
- SOC 和 SOH 标签来源明确。
- 不存在同一电池同时进入训练集和测试集的问题。
- 工况和动态事件具有明确的划分方法。
- 数据处理流程能够直接转化为代码模块。
- 短时和长时样本结构明确。
- 输出完整的数据处理设计文档和待开发文件清单。

风险检查点：

- 检查是否错误生成不存在的 SOH 标签。
- 检查是否将协议容量变化误认为老化。
- 检查是否采用随机行划分造成数据泄漏。
- 检查是否在实时预处理中使用未来数据。
- 检查是否在电流突变附近过度平滑电压。
- 检查是否对长时间缺失数据进行不合理插值。
- 检查不同数据集的电流方向和容量基准是否一致。
- 检查 SNL 数据是否被错误用于完整 SOH 主训练。

结束时应记录：

- 每个数据集的用途。
- SOC 标签生成规则。

- 工况和事件分类方法。
- 短时和长时窗口设置。
